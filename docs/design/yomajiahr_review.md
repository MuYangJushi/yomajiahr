# Yoma+HR 智能助手方案评审意见

## 一、整体评价

这是一份方向正确、结构完整、明显偏企业级落地的 HR AI 平台方案。它的价值不在于“做一个聊天机器人”，而在于试图把 HR 的问答、流程、审批和数据分析整合为一个可治理的执行系统。

## 二、主要优点

1. **场景选择合理**：招聘、入离职、政策问答、数据分析、排班考勤，覆盖 HR 的高频主流程。
2. **架构层次清晰**：前端交互层、OpenClaw 核心层、数据与集成层之间职责分明。
3. **治理意识较强**：加入权限网关、审批引擎、日志审计、双重确认，说明方案意识到 HR 数据的敏感性。
4. **落地路径清楚**：从 RAG 问答开始，逐步扩展到流程与数据智能，实施节奏较稳健。
5. **与企业系统结合度高**：没有停留在纯模型思维，而是强调 HRIS、招聘平台、日历、数据仓库的集成。

## 三、核心风险

1. **权限体系仍偏概念化**：文档提到权限网关，但没有给出明确的角色-资源-动作矩阵。
2. **审批与自动执行边界不够细**：哪些动作只是建议，哪些动作允许自动触发，定义还不够严格。
3. **RAG 评测标准缺失**：只写了“回答附来源”，但缺少准确率、转人工率、越权拦截率等量化指标。
4. **数据分析 Agent 的数据口径未定义**：例如流失率、人效、加班时长等指标需要统一口径，否则结果难以被业务接受。
5. **多 Agent 协同异常处理不足**：工具失败、外部系统超时、重复执行、幂等控制、人工接管等还需补充。

## 四、建议优先补充的内容

### P0：必须补

- 角色权限矩阵
- 工具调用白名单与字段级脱敏规则
- 审批流状态机与人工接管机制
- RAG 评测与审计指标
- 高风险动作清单

### P1：建议尽快补

- 核心实体模型与数据字典
- 数据分析指标口径说明
- 多渠道接入的统一身份映射方案
- 失败补偿、幂等、重试和告警机制

### P2：后续增强

- 预测模型（离职风险、招聘需求预测）
- 多语言支持
- 更细粒度的运营看板与质量监控

## 五、产品与架构判断

从产品视角看，最适合先落地的是政策问答 Agent；从架构视角看，最关键的不是先堆更多 Agent，而是先把权限、审批、审计和系统集成边界做扎实。

## 六、结论

这份方案已经具备“企业可讨论、可试点、可分阶段推进”的基础。要想真正进入生产环境，下一步最重要的不是继续写更漂亮的架构图，而是把权限、审批、失败处理和指标体系补成可实施规范。
