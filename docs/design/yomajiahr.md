# Yoma+HR — 基于 OpenClaw 的企业 HR 智能助手整体设计思路

---

## 一、产品定位

面向企业 HR 团队的 AI 工作台，核心价值：**减少重复性事务工作，让 HR 聚焦在人的问题上**。

## 三、核心功能模块

### 🧑‍💼 1. 招聘助手 Agent

- 根据 JD 自动筛选简历，打分排序
- 生成面试问题（按岗位/候选人背景定制）
- 发送面试邀约邮件/消息
- 汇总面试官反馈，生成录用建议

### 📋 2. 入职/离职流程 Agent

- 自动生成 Onboarding checklist
- 触发跨部门任务（IT开账号、财务配置薪资、行政寄物品）
- 离职流程自动推进，敏感权限提醒撤销

### 📄 3. 政策问答 Agent（知识库 RAG）

- 接入公司规章制度、假期政策、薪酬规则文档
- 员工随时问："年假怎么算？" "病假需要什么证明？"
- 回答有据可查，附来源页码

### 📊 4. 数据分析 Agent

- 人员流失率趋势分析
- 部门人效对比报告
- 招聘漏斗分析（从投递到 offer 转化率）
- 自动生成可视化图表 + 文字解读

### 🗓️ 5. 排班 & 考勤助手

- 自动排班建议（基于历史数据 + 员工偏好）
- 异常考勤预警（迟到/缺勤聚集）
- 对接钉钉/飞书考勤数据

## 四、OpenClaw 关键设计

### Agent 编排策略

```
用户提问
   │
   ▼
路由 Agent（意图识别）
   ├── 招聘相关 → 招聘 Agent
   ├── 政策查询 → RAG Agent
   ├── 数据分析 → 分析 Agent
   └── 流程审批 → 流程 Agent
```

### 工具集成（MCP）

| 工具                      | 用途                   |
| ------------------------- | ---------------------- |
| HRIS API                  | 读取员工档案、组织架构 |
| 招聘系统（猎聘/Boss直聘） | 拉取简历、更新状态     |
| 企业邮件/日历             | 发邀约、安排面试       |
| 文档知识库                | 政策 RAG 检索          |
| 数据库                    | 人员数据分析           |

### Prompt 工程要点

- 每个 Agent 有独立 **System Prompt**，明确角色边界
- 关键决策（如 offer 发放）需要 **人工确认节点**，AI 不自动执行
- 敏感信息（薪资、绩效）做 **权限分级**，普通员工不可查

---

## 五、数据安全设计

- 所有 HR 数据走**私有化部署**或**企业专属 API Key**，不走公共云
- 员工个人信息做**脱敏处理**后再送入模型
- 操作日志全量记录，支持审计
- 关键操作（删除档案、发 offer）需双重确认

---

## 六、落地路径建议

```
第一阶段（1-2个月）：快速验证
  └── 先做政策问答机器人（RAG最容易上线，价值明显）

第二阶段（2-4个月）：扩展核心流程
  └── 接入招聘筛选 + 入职流程自动化

第三阶段（4-6个月）：数据智能
  └── 人员数据分析 + 预测性洞察（离职风险预测等）
```
